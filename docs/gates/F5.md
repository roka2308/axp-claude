## Gate criterion

> A reviewer can answer `What can this user do, where, and why?` from the UI
> without inspecting database rows.

**Answered on one page per person** (`/admin/users/<id>`), which opens with the
answer and only then shows what produces it:

- **What they can do, where:** one row per scope (platform, tenant, project),
  the capabilities in words ("Veröffentlichte Dashboards ansehen", not
  `dashboard.read_published`).
- **Why:** each row carries its chains, read left to right — _Vera Viewer →
  Gruppe Portal-Leser → Rolle Viewer → im Projekt Employee Portal_.
- **Which data:** one row per dashboard with _Ansehen_ and _Bearbeiten_. A yes
  names both halves (role and grant); a no names the half that is missing —
  "Nein - Freigabe fehlt", "Nein - Rolle fehlt", or both.

The same answer from the other side: _Rollen & Rechte → Nach Dashboard_ lists
who can open a dashboard and why. And from the person's own side: _Mein Profil
→ Meine Rechte_.

The gate run checks the answer is complete (every capability and every verdict
explained, every reason worded) and **true**: for every person who can sign in
and every dashboard, "may view" in the answer is exactly "the dashboard opens"
on the request path.

## Security tests (development plan)

| Test                                                           | Result | Evidence                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tenant Admin cannot assign Platform Admin                      | pass   | never offered (the assignable roles are computed server-side), refused with 403 when sent anyway, and a tenant admin cannot reach into another tenant; in the browser the role select holds no "Platform Admin"                                                                                    |
| Platform Admin without object/data grant cannot open analytics | pass   | layout, tiles and detail view answer 403, the library and search list nothing, while tenant administration still works; the Tenant Detail says "sehen aber keine seiner Daten". A tenant admin is refused the same way                                                                             |
| Group/direct grant accumulation correct                        | pass   | access survives removing either path while the other remains; the preview predicts "no effect" for a direct grant on top of a group grant, and a loss for leaving the group                                                                                                                        |
| No deny rules exist                                            | pass   | access levels are exactly `view` and `edit` in the contract and the schema; a grant with `access: "deny"` is refused as invalid (422)                                                                                                                                                              |
| Deactivated user/session behaviour                             | pass   | deactivation ends every session at once (the old token answers 401 on the next request), sign-in is refused, Effective Access says "Konto nicht aktiv" while keeping the rows; reactivation restores exactly what the account held. Deactivating needs a password confirmed in the last 15 minutes |

## Decisions recorded

[ADR 0006](../adr/0006-data-access-needs-role-and-grant.md): data access needs
a role capability **and** an object grant. Until Phase 4 a viewer role in a
project opened every published dashboard in it — "no role grants automatic
data access" was written down but not enforced. It is now, on every path that
reads data, and the creator of a dashboard receives an edit grant on it.

[DEV-005](../../DEVIATIONS.md): there is no mail transport yet. Invitation links
are shown once to the administrator to pass on, and a local account's email
address is not self-service until confirmation mail exists (Phase 8).

## Defects found and fixed during the phase

| Defect                                                                  | Impact                                                                                                                          | Fix                                                                                                              |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Roles opened data by themselves                                         | A project viewer saw every published dashboard, whether or not it was shared — the invariant existed only in text               | ADR 0006; the 56 integration tests that relied on it now grant access explicitly                                 |
| Deactivation and reactivation were missing from the tenant audit        | The events were written without a tenant, so the tenant's own trail never showed them — found by the gate run                   | The tenant the change was made from is recorded; the audit integration test now covers it                        |
| The app shell widened the page to its widest table                      | On a phone, the user detail page scrolled sideways by 176 px — the grid column's minimum was its content                        | `minmax(0, 1fr)`: tables scroll inside their own container                                                       |
| A select was as wide as its longest option                              | On an iPhone the grant form pushed the page 35 px sideways                                                                      | `SelectField` takes the width it is given                                                                        |
| The top-bar search collapsed to a sliver on phones                      | It was squeezed between brand and account links                                                                                 | Below 40 rem it gets a row of its own                                                                            |
| A rate-limit refusal read "Die Anfrage konnte nicht verarbeitet werden" | Sign-in refused for too many attempts gave no reason and no time to wait — found when the gate's own sign-ins tripped the limit | `rate_limited` product error with the seconds to wait; an API test covers it                                     |
| A viewer test measured the close control before its stylesheet arrived  | On a cold server the 44 px check could fail although the control is 44 px                                                       | The test polls the size until layout settles                                                                     |
| Typing a hyphen into a slug removed it                                  | The slug field re-derived the slug on every key, trimming the trailing hyphen                                                   | Typed input keeps it; only a slug derived from the name is trimmed. German umlauts become `ae`, `oe`, `ue`, `ss` |
