# Gate F9 — Themes, Entitlements, Diagnostics and Release Metadata

Status: **passed**
Date: 2026-10-04
Product version: 0.1.0 · schema version 9
Reproduce with: `npm run gate:f9` (or `npm run gate:f9:local` without Docker;
`WEB_PORT=3100` in the environment if another program holds port 3000)

Phase 9 of `03_Claude_Code_Development_Plan_v1.0.md`, implementing D9 themes,
entitlements, release metadata and diagnostics (Master Spec §16, §23–§24).
`scripts/verify-gate-f9.mjs` runs against a real stack and the canonical
fixture, from an empty database. It drives the API as the platform
administrator, the tenant administrator, an editor and a viewer, reads the
database where only the database can prove a claim (no version created, no
row deleted, nothing stored in clear text) and lets the worker delete an
expired diagnostic bundle on its own.

## Decisions recorded

- [ADR 0011](../adr/0011-themes-are-tokens-entitlements-are-not-permissions.md):
  a theme is a map of allowlisted tokens to validated values, publishing is
  gated by contrast including dependents, entitlements are a third state that
  never deletes configuration, diagnostics are allowlist-built and scanned.
- DEV-007 resolved: exports are drawn with the theme that applies to the
  dashboard's project.

## Defects found and fixed during the phase

| Defect                                                      | Impact                                                                                          | Fix                                                                                       |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| The default control border was 1.47:1 against cards         | Input and button outlines failed WCAG 1.4.11 in the shipped theme                               | `--border-default` and `--border-strong` raised in light and dark; a drift test pins them |
| A theme failing its own checks was blamed on its dependents | The message pointed an administrator at the wrong theme                                         | the theme's own failures are reported first                                               |
| The viewer waited for the theme before its first flush      | A fast tile could skip its loading state, so the streamed document no longer showed every state | the stylesheet is fetched alongside the layout, before rendering                          |
