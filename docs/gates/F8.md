# Gate F8 — Scheduled Reporting and Attention Center

Status: **passed**
Date: 2026-10-03
Product version: 0.1.0 · schema version 8
Reproduce with: `npm run gate:f8` (or `npm run gate:f8:local` without Docker;
`WEB_PORT=3100` in the environment if another program holds port 3000)

Phase 8 of `03_Claude_Code_Development_Plan_v1.0.md`, implementing scheduled
reporting and the Attention Center of D8 (Master Spec §15, Shared Contract
§12). `scripts/verify-gate-f8.mjs` runs against a real stack and the canonical
fixture, from an empty database. Mail goes to a small SMTP server inside the
script, so the gate reads what was really sent: attachments, subjects,
recipients. Scheduled occurrences are set a few minutes ahead and the gate
waits for the worker to run them on its own.

## Acceptance criteria

| Criterion (development plan)                                        | Result | Evidence                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Schedules use Published Runtime                                     | pass   | the draft is renamed before a run; the PDF actually mailed shows the published name and version, never the draft name; the run records the published version it read                                                                                                       |
| Suspended/offboarding tenant stops reports/shares/customer jobs     | pass   | while suspended a due occurrence is recorded as skipped and no job runs, the shared link answers "unavailable", "send now" is refused, no mail leaves; a job queued before the suspension is cancelled when claimed (`reporting.test.ts`); reactivated, everything resumes |
| Repeated failure is grouped                                         | pass   | three failed runs of one schedule are one Attention item counted 3×, the owner gets one notice mail, not three; when a run succeeds again the item resolves itself                                                                                                         |
| Operational attention items are not analytics recommendation alerts | pass   | the store's `kind` enum is exactly five operational kinds; there is no metric, value or threshold column and no route to create an item; every item any demo account sees is operational; a contract test pins the list                                                    |

### Build list

| Build item                                   | Where it is shown                                                                                                                                    |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| JobQueue abstraction                         | `JobQueue` / `MySqlJobQueue`: idempotent enqueue, lease-based claim (`SKIP LOCKED`), complete, cancel                                                |
| Reliable worker claim/retry/fail/complete    | `JobRunner` in the worker; retry after 1, 5, 15 minutes, then `dead`; expired leases return to the queue; the gate makes the mail server refuse once |
| ReportSchedule                               | `report_schedules` and `report_runs`; Projekt → Reports with list, history, edit, pause, send now, delete                                            |
| Relative periods and explicit time zone      | the period is resolved at the moment the run was due, in the site calendar; when it runs is decided in the schedule's IANA zone, DST-safe            |
| Daily/weekly/monthly/quarterly/simple custom | `nextOccurrence` with unit tests, including the switch to winter time; "custom" is a chosen set of weekdays                                          |
| PDF/XLSX delivery                            | rendered in the worker, attached, one mail per recipient, nothing stored                                                                             |
| PPTX behind exporter stability gate          | `REPORTS_PPTX_ENABLED`, off: schedules cannot choose PPTX, the form says why                                                                         |
| Recipient permission validation              | at saving (refused) and at every run (left out, named in the run, owner told)                                                                        |
| Attachment/link delivery abstraction         | `attachment` or `link`; a link stores and renders nothing, the recipient signs in                                                                    |
| Attention Center model                       | `attention_items` with group key, occurrences, first/last seen, acknowledge, auto-resolve                                                            |
| Role-aware routing                           | audience capability in the item's project or tenant, plus an owner                                                                                   |
| Grouped repeated problems                    | one item per problem; a resolved or acknowledged problem that returns is open again                                                                  |
| In-app first + selective mail                | top bar "Aufmerksamkeit" with a count; mail only for `action_required` items with an owner, once per group                                           |
