## Decisions recorded

**Drift review is a state on the mapping, not a new version.** Detection can
say a mapping no longer resolves; it cannot say what to do about it. Somebody
deciding "the dimension really is gone, and that is expected" is an answer the
product has to remember, or the same warning is raised forever and stops being
read. The review is stored with a fingerprint of what it was about — the
binding's target and whether the site had it — so it expires by itself when the
situation changes, rather than silently signing off on something new.

**A `'use server'` module may export only async functions.** Next enforces this
at runtime, not at build time: a constant exported from an action file builds
cleanly and breaks the page the first time somebody opens it. That cost a debug
cycle in Phase 1 and again here, so `apps/web/src/lib/server-actions.test.ts`
now reads every such module and fails on a non-function export.

**Adopting a new semantic version is an editorial act.** A widget holds a
version id, and publishing pins what the widget holds (Shared Contract §7).
Activating a new version therefore reaches no dashboard until an editor puts it
there. The gate demonstrates this explicitly, including that a blind republish
does not adopt it — the alternative, where publishing silently pulls in the
newest active version, would make "published is immutable" true of the snapshot
and false of its meaning.

## Defects found and fixed during the phase

| Defect                                                                                 | Impact                                                                                                                                                              | Fix                                                                                                                       |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| A formula that could not combine reported "an unexpected error occurred"               | The API had been sending a precise key and parameters all along; the copy for it existed in neither language, so `resolveError` fell through to the generic message | All fourteen formula and score validation keys written in `de` and `en`, with unit and scope names rendered inline        |
| A custom metric was not executable at all                                              | `sourceMetricFor` threw `semantic_type_not_executable` for anything but a native metric, so a score containing a custom metric could not even be previewed          | The requirement is resolved through the project's source mappings; an unmapped one enters the result as the absence it is |
| An unmapped input failed the whole query                                               | One requirement nobody had mapped would have taken a dashboard down with it, instead of being reported as a setup question with a named subject                     | `missing` with cause `no_mapping`, carried per data point; the surrounding query still answers                            |
| `POST …/versions` returned a bare version, `POST …/semantic-definitions` a wrapped one | Two routes on one resource with two shapes — a trap for the next caller, and one this gate walked straight into                                                     | Both wrapped                                                                                                              |
| Zod stripped unknown keys rather than refusing them                                    | A node carrying an extra `eval` field was accepted, and something other than what was sent was stored                                                               | Every object in the semantic schemas is strict                                                                            |
| The version history list had no accessible name                                        | A screen-reader user heard a bare list                                                                                                                              | `aria-label`, which is also what lets a test tell "Version 1" in the history from "Aktiv in Version 1" in the table       |
| Shipped glossary text never reached an existing installation                           | `ensureGlobalDefinition` returned early for a definition that already existed, so a better wording in a later release would never land                              | Name and description are updated in place; the body is not, because that would be a new business version                  |

## Deviations

[DEV-004](../../DEVIATIONS.md): of the six source binding kinds the product can
record, one is executable. A mapping to a custom dimension, an event, a goal or
site search is stored, shown and versioned exactly as specified, but fetching it
needs a Matomo call shape the connector does not have — so the value comes back
as `missing` with a stated reason rather than as a number. Each of the four is a
different API call with its own capability requirement, and building them
against a mock adapter with no real Matomo to verify against would produce four
guesses. None of the F3 criteria depend on which kinds execute.

[DEV-002](../../DEVIATIONS.md) (`not_calculable` as a cause of `missing` rather
than an eleventh state) is exercised heavily by this phase and remains open for
the first cross-track comparison.
