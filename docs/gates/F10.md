# Gate F10 — MVP Hardening and Acceptance

Status: **passed**
Date: 2026-10-20
Product version: 0.1.0 · schema version 10
Reproduce with: `npm run gate:f10` (or `npm run gate:f10:local` without Docker;
`WEB_PORT=3100` in the environment if another program holds port 3000)

Phase 10 of `03_Claude_Code_Development_Plan_v1.0.md`: "All MVP acceptance
criteria pass. Remaining items are explicitly classified as MVP+, Performance
Gate, Production Readiness or On Hold." The item-by-item verdict with evidence
is [`docs/acceptance/mvp-acceptance.md`](../acceptance/mvp-acceptance.md); the
gate reads it and fails if any item is unaccepted or unclassified.

`scripts/verify-gate-f10.mjs` runs every workstream against a real stack. The
database it hardens is not seeded by this release: the previous release
(`v0.9-themes-entitlements-diagnostics`) is checked out in a worktree and
writes its schema and the canonical fixture with its own code, and this
release upgrades it - so the rest of the gate runs on an upgraded installation.
Mail goes to an SMTP server inside the script; the stack's output is written to
`.local/gate-f10/*.log` and reviewed at the end.

## Defects found and fixed during the phase

| Defect                                                                                   | Impact                                                                                                                                         | Fix                                                                                                                      |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Sign-in lockout counted the web server's address, threshold 5                            | Five mistyped passwords by anyone locked every user out for up to 15 minutes                                                                   | Lockouts count the visitor's address (trusted header from the web server); an address locks after 50, an account after 5 |
| Rate limits counted the web server's address                                             | All visitors shared one budget per route                                                                                                       | Per session when signed in, per visitor otherwise (ADR 0012)                                                             |
| Routes shared one `onRequest` array (`guard`), and the rate limiter added its hook to it | A limit of one route (e.g. 10/min for re-authentication) applied to every route sharing the object - the profile page failed, tiles went empty | Each route gets its own hook arrays before the limiter registers; a test proves an unlimited route stays unlimited       |
| No self-service password recovery                                                        | "Invite und Recovery" (Master Spec §6) only half built                                                                                         | `/forgot-password`, `/reset-password`, non-enumerating, single-use, ends all sessions                                    |
| Matomo request deadline ended at the response headers                                    | A Matomo that answered headers and then stalled held the request forever                                                                       | The deadline covers the body                                                                                             |
| Request log records were empty                                                           | Operators could not see which request a log line belonged to                                                                                   | Method, path without query, status                                                                                       |
| An internal lockout message carried the account's address into the log                   | Personal data in logs                                                                                                                          | Message names the kind of lock; the log sanitiser masks any address to its domain                                        |
| Invitation token in an API URL                                                           | A token in a URL ends up in access logs                                                                                                        | Inspection moved into the request body                                                                                   |
| Muted text on tinted surfaces at 4.3:1                                                   | WCAG 1.4.3 failures on the dashboard scope, gallery and setup                                                                                  | `--text-muted` darkened; the theme check covers muted text on those surfaces                                             |
| No error boundary                                                                        | Unexpected errors showed the framework's English page                                                                                          | Localized error and not-found pages with a reference number                                                              |
| Forgot-password button stayed disabled for input typed before hydration                  | Mobile Safari users could not submit a filled form                                                                                             | The form reads the field on submit                                                                                       |
| Two audit actions never written; three without a label                                   | Setup changes untraceable; raw keys in the audit view                                                                                          | Setup-step changes audited; labels added; both checked by tests                                                          |
| `next` critical advisory (next/og)                                                       | Not used by the product, but shipped                                                                                                           | `next` 16.3.8                                                                                                            |
| `sharp` and `source-map-js` advisories published during the phase                        | High-severity DoS/librsvg issues in dependencies of `next` and the build tools                                                                 | `sharp` 0.35.5, `source-map-js` 1.2.2 (non-breaking update)                                                              |
