## Defects found and fixed during the gate

| Defect                                                              | Impact                                                                                 | Fix                                                                                            |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `affectedRows` read from the wrong level of the mysql2 result tuple | Session revocation and cleanup reported 0 rows; the audit trail recorded a wrong count | `affectedRows()` helper in `@axp/db`, used at all three call sites                             |
| tsup bundled CommonJS dependencies into the ESM output              | The built API crashed at startup with "Dynamic require of fs is not supported"         | External rule now bundles workspace packages only and leaves every third-party import external |
| Root npm scripts swallowed forwarded arguments                      | `npm run bootstrap-admin -- --json` was parsed by npm itself                           | Scripts end with `--` so appended arguments reach the workspace script                         |
| Correlation ID always visible on error                              | D10 asks for technical detail on demand only                                           | `ErrorCallout` puts it behind a disclosure                                                     |

## Environment note

Docker Desktop could not start on the development machine: Windows 10 Home
requires the WSL 2 backend, and enabling the Virtual Machine Platform feature
fails with `ERROR_SXS_ASSEMBLY_MISSING` (a damaged component store, unrelated to
this product).

The gate was therefore demonstrated against a portable MySQL 8.4.10 from the
official Oracle ZIP distribution, run as a user process with server settings
identical to `docker-compose.yml` (`scripts/local-mysql.mjs`). `docker-compose`
remains the documented default; `npm run gate:f0` uses it, and
`npm run gate:f0:local` uses the portable server.

This is a local development environment difference, not a product deviation:
nothing in the product knows which of the two it is talking to.
